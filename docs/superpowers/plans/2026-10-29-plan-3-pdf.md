# Plan 3 — PDF Rendering (Track 3) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A `fap-pdf` crate that renders any puzzle file as a tiled wall poster: pages that line up when trimmed, with footers, labels, overlap strips, heavy 5-cell lines and crop marks, plus optional staff sheets. Also a `fap render` CLI command.

**Architecture:** There are two layers.

- **Pure layout layer**, in millimetres with no PDF types: the settings schema, paper table, page geometry, tile grid, and label and footer text. Every decision about what goes where lives here, and it is test-driven exhaustively.
- **Thin drawing layer:** a small `Canvas` wrapper over `pdf-writer` turns a `Layout` plus a `Puzzle` into PDF bytes. Tests parse the output with `lopdf` to count pages, read page sizes (MediaBoxes) and extract text.

Settings live in the project's opaque `[pdf]` table (Plan 0). This crate owns that table's schema through `PdfSettings::{from_table, to_table}`.

**Tech Stack:**

- **`pdf-writer`** (MIT/Apache-2.0) for writing PDFs. It is low-level and light on dependencies. It writes base-14 Type 1 fonts directly (Helvetica, WinAnsiEncoding), so no font is embedded. It adds no timestamps, so output is deterministic.
- **`lopdf`** (MIT), as a dev-dependency only, for parsing PDFs in tests.
- **`serde`/`toml`** for settings and **`thiserror`** for errors.

Alternatives considered: `printpdf` (MIT) has a heavier API that has changed between versions, and `krilla` (MIT/Apache) requires an embedded TrueType font. Base-14 Helvetica keeps files small and is available in every viewer and printer.

**Spec:** `docs/superpowers/specs/2026-10-29-fill-a-pix-design.md` §7 (PDF rendering), §8 Track 3, §9 PDF tests. Plan 0 (`docs/superpowers/plans/2026-10-29-plan-0-foundation.md`) defines the `fap-core` API used here: `Puzzle`, `Clue`, `Grid`, `Pos`, `Image`, `format::read_puzzle_file`, `format::read_project_file`.

**Prerequisite:** Plan 0 is merged. Work in a dedicated git worktree (superpowers:using-git-worktrees) on branch `track-3-pdf`. Test input comes from `fap clue-all` / `Puzzle::fully_clued`, so this track does not depend on Track 2.

> **Plan 0 final-review additions (merged after this plan was drafted):** `fap-core` now also provides `Regions::validate()`, `Project::validate()`, `regions::MAX_REGION_ID` (= `u32::MAX / 2`; larger IDs are rejected on load) and `pub use toml` (use `fap_core::toml` instead of adding your own `toml` dependency). `Regions` equality ignores the internal `next_id` cursor, so a saved and reloaded value compares equal. `write_project_file` / `write_puzzle_file` validate before writing and return `Err` without touching the old file. `Puzzle::validate()` also validates its regions and rejects digits above 9.   - `cell_mm` must be in [10, 40] inclusive (spec).
  - `margin_mm` must be in [5, 30] inclusive. This is the designer's call; crop marks need at least 5 mm.
- **Fixed geometry constants.** These are `pub const` in `layout.rs`. Tests reference the constants, never literals, and the builder may tune them after the visual checks.
  - `FOOTER_BAND_MM = 8.0`, reserved at the bottom of every page.
  - `LABEL_BAND_MM = 10.0`, reserved on both sides of an axis whose labels are enabled. Row labels get left and right bands; column labels get top and bottom bands.
  - Line widths: `THIN_MM = 0.2`, `HEAVY_MM = 0.5`, `BORDER_MM = 0.8`, `CROP_MM = 0.15`.
  - Crop mark geometry: `CROP_GAP_MM = 1.0`, `CROP_LEN_MM = 4.0`.
  - `GREY = 0.6`, the grey level for overlap strips.
- **Same grid position on every page:** label bands and overlap strips are reserved on every tile, even where nothing is drawn in them, so that trimmed tiles line up.
- **Deterministic output:** the same puzzle and settings produce a byte-identical PDF, with no dates and no random IDs.
- **Text:** base-14 Helvetica in WinAnsiEncoding. Characters outside WinAnsi are replaced by `?`.
- **Public API:** `fap_pdf` re-exports `PdfError`, `PdfSettings`, `Paper`, `Orientation`, `LabelStyle`, `Sides`, `StaffSheets`, `render` and `RenderOutput` at the crate root. It exposes the modules `labels`, `layout`, `text` and `canvas`.

**Interfaces:**
- Consumes: `toml::Table`, as stored in `fap_core::Project::pdf`.
- Produces:
  - `pub enum Paper { Letter, A4, A3, Tabloid, Custom { width_mm: f64, height_mm: f64 } }`.
    - Serde form: lowercase strings `"letter" | "a4" | "a3" | "tabloid"`, or an inline table `{ width_mm = …, height_mm = … }` for a custom size.
    - `Paper::portrait_mm(&self) -> (f64, f64)`.
    - `Paper::name(&self) -> String`: `"Letter"`, `"A4"`, `"A3"`, `"Tabloid"`, or for custom sizes e.g. `"Custom 100×150 mm"`.
  - `pub enum Orientation { Portrait, Landscape, Auto }` (serde lowercase).
  - `pub enum LabelStyle { None, Numbers, Letters }` (serde lowercase).
  - `pub struct Sides { pub top: bool, pub bottom: bool, pub left: bool, pub right: bool }`, defaulting to all false.
  - `pub struct StaffSheets { pub summary: bool, pub assembly_map: bool, pub solution: bool, pub separate_file: bool }`.
  - `pub struct PdfSettings { pub paper: Paper, pub orientation: Orientation, pub cell_mm: f64, pub margin_mm: f64, pub row_labels: LabelStyle, pub col_labels: LabelStyle, pub labels_on_every_tile: bool, pub overlap: Sides, pub crop_marks: bool, pub staff: StaffSheets }`.
    - All settings types derive `Clone, Debug, PartialEq` and serde, with `#[serde(default)]` throughout.
    - **Defaults (designer's call):** Letter paper, Auto orientation, 15 mm cells, 12 mm margin, row labels `Numbers`, column labels `Letters`, labels on outer edges only, no overlap, crop marks on, all three staff sheets on, `separate_file = true`.
  - `PdfSettings::from_table(t: &toml::Table) -> Result<PdfSettings, PdfError>`. Missing keys take their defaults and unknown keys are ignored. A bad value gives `PdfError::InvalidSettings(msg)`, where the message names the key.
  - `PdfSettings::to_table(&self) -> toml::Table`.
  - `PdfSettings::validate(&self) -> Result<(), PdfError>`. It returns `CellSizeOutOfRange` outside [10, 40], `MarginOutOfRange` outside [5, 30], and `InvalidSettings` for a non-positive custom paper size.
  - `pub enum PdfError { InvalidSettings(String), CellSizeOutOfRange(f64), MarginOutOfRange(f64), PaperTooSmall { paper: String, cell_mm: f64, cols_fit: usize, rows_fit: usize } }` (thiserror). The display strings are:
    - `"invalid PDF settings: {0}"`
    - `"cell size {0} mm is outside 10–40 mm"`
    - `"margin {0} mm is outside 5–30 mm"`
    - `"{paper} is too small for {cell_mm} mm cells with these settings (fits {cols_fit} columns × {rows_fit} rows)"`

### Task 3: Page layout, tile grid and footer text

**Files:**
- Create: `crates/fap-pdf/src/layout.rs`
- Test: `crates/fap-pdf/tests/layout.rs`

**Interfaces:**
- Consumes: `PdfSettings` and `PdfError` (Task 1); `labels` (Task 2).
- Produces:
  - The geometry constants listed under Global Constraints, as `pub const`.
  - `pub struct Tile { pub tile_row: usize, pub tile_col: usize, pub rows: Range<usize>, pub cols: Range<usize> }`. Tile indices are zero-based; `rows` and `cols` are the puzzle row and column ranges the tile covers.
  - `pub struct Layout { pub page_mm: (f64, f64), pub landscape: bool, pub cell_mm: f64, pub rows_per_page: usize, pub cols_per_page: usize, pub tile_rows: usize, pub tile_cols: usize, pub grid_origin_mm: (f64, f64), pub tiles: Vec<Tile> }`.
    - `tiles` is in page order: row-major, so top to bottom, then left to right within each row of tiles.
    - `grid_origin_mm` is the (x, y) position of the tile's own first cell. It is the same on every page.
  - `plan_layout(puzzle_width: usize, puzzle_height: usize, s: &PdfSettings) -> Result<Layout, PdfError>`, computed as follows:
    1. Call `s.validate()`.
    2. For each candidate orientation (just the requested one, or both for `Auto`), compute:
       - `avail_w = page_w − 2·margin − (row_labels ≠ None ? 2·LABEL_BAND_MM : 0) − cell·(overlap.left + overlap.right)`
       - `avail_h = page_h − 2·margin − FOOTER_BAND_MM − (col_labels ≠ None ? 2·LABEL_BAND_MM : 0) − cell·(overlap.top + overlap.bottom)`
       - `cols_per_page = floor(avail_w / cell)` and `rows_per_page = floor(avail_h / cell)`. If either is below 1, that orientation fails with `PaperTooSmall`.
    3. Set `tile_cols = ceil(width / cols_per_page)` and `tile_rows = ceil(height / rows_per_page)`.
    4. For `Auto`, pick the orientation with fewer pages; on a tie, pick portrait. If both orientations fail, return the portrait error.
    5. Set `grid_origin_mm = (margin + left_label_band + overlap.left·cell, margin + top_label_band + overlap.top·cell)`.
  - `pub struct FooterText { pub left: String, pub center: String, pub right: String }`.
  - `footer_text(layout: &Layout, tile: &Tile, s: &PdfSettings, title: Option<&str>) -> FooterText`, where:
    - `left` is the title, or `""` if there is none;
    - `center` is `"{rows} · {cols}"`, built from `range_text("Row", "Rows", s.row_labels, …)` and `range_text("Col", "Cols", s.col_labels, …)` joined by `" · "` (U+00B7);
    - `right` is `"Tile: {ordinal(tile_row+1)} from top (of {tile_rows}), {ordinal(tile_col+1)} from left (of {tile_cols})"`.

### Task 4: Text encoding and Helvetica metrics

**Files:**
- Create: `crates/fap-pdf/src/text.rs`
- Test: `crates/fap-pdf/tests/text.rs`

**Interfaces:**
- Produces (`fap_pdf::text`):
  - `winansi(s: &str) -> Vec<u8>`. Printable ASCII and Latin-1 characters map to themselves. These characters get their WinAnsi bytes: `–` → 0x96, `—` → 0x97, `·` → 0xB7, `×` → 0xD7, `‘’“”` → 0x91–0x94, `…` → 0x85. Anything else becomes `b'?'`.
  - `helvetica_width(byte: u8) -> u16`: the advance width of a WinAnsi byte, in 1/1000 em. Transcribe the values from Adobe's Core14 `Helvetica.afm` for bytes 0x20–0x7E, 0xA0–0xFF and the punctuation listed above. Any other byte returns 556.
  - `text_width_mm(s: &str, size_mm: f64) -> f64`: the sum of `helvetica_width` over `winansi(s)`, times `size_mm / 1000`.
  - `pub const HELVETICA_CAP_HEIGHT: f64 = 0.718;` (a fraction of the em, from the AFM).

### Task 10: Staff sheets

**Files:**
- Create: `crates/fap-pdf/src/staff.rs`
- Modify: `crates/fap-pdf/src/lib.rs` (`render` appends the staff pages or puts them in a separate PDF)

**Interfaces:**
- Produces:
  - `staff::summary_page(c: &mut Canvas, p: &Puzzle, l: &Layout, s: &PdfSettings)`: one portrait page on the poster's paper. Each line below is its own `Tj`, in this order:
    1. the title, or `"Untitled puzzle"`;
    2. `"Size: {w} columns × {h} rows"`;
    3. `"Paper: {paper.name()} {portrait|landscape}, cell {cell} mm, margin {margin} mm"`;
    4. `"Tiles: {tile_rows} rows × {tile_cols} columns ({n} pages)"`;
    5. `"Digit clues: {n}"`, `"Given cells: {n}"` and `"Regions: {k}"`;
    6. `"Generation:"` and `"Stats:"`, each followed by one `"  {key} = {value}"` line per entry of the puzzle's `generation` or `stats` table. Entries are in sorted key order, nested tables are flattened as `a.b`, and the heading is omitted when its table is empty.

    Numbers are printed without a trailing `.0` (`15 mm`, `22.5 mm`).
  - `staff::assembly_map(c: &mut Canvas, l: &Layout)`: one page.
    - It has the heading `"Assembly map"`, then one box per tile, laid out like the poster and scaled to fit the page.
    - Each box contains `"{tile_row+1},{tile_col+1}"` as a single `Tj`.
    - Row ranges run down the left edge (one `range_text` per tile row) and column ranges along the top.
    - The legend line reads `"Box r,c = r-th tile from top, c-th from left. Top of poster is up."`.
  - `staff::solution_pages(c: &mut Canvas, p: &Puzzle, s: &PdfSettings)`: the solution image.
    - Shaded cells are filled black, with grey lines every 5 cells and a thin border.
    - The cell size is the largest value ≤ 5 mm at which the whole puzzle fits on one page in either orientation, after the margins and an 8 mm heading band. If that is below 1.5 mm, use 1.5 mm and paginate with the same row-major tiling.
    - Each page has the heading `"Solution"`, or `"Solution · {rows} · {cols}"` when there are several pages.
  - `render` produces the staff pages when any of `summary`, `assembly_map` or `solution` is enabled, in that order.
    - If `separate_file` is set, the staff pages go in `RenderOutput.staff` as their own PDF, and `poster` holds only the tiles.
    - Otherwise they are appended to `poster`, and `staff` is `None`.
    - When no staff sheet is enabled, `staff` is `None`.
